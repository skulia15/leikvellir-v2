playground creation, validation\n- **Security functions** - file validation, authentication\n- **User interactions** - form submission, file uploads\n- **Error handling** - what happens when things go wrong\n\n#### ❌ We Don't Test:\n- **Third-party libraries** - Next.js, React, etc.\n- **Browser APIs** - we mock them instead\n- **External services** - database, file system (mocked)\n\n## 🔧 Key Concepts Explained\n\n### Mocking Strategy\n```typescript\n// ❌ Don't test external dependencies\ntest('database connection works', () => {\n  // This is slow and unreliable\n})\n\n// ✅ Mock external deps, test your logic\ntest('playground creation logic', () => {\n  mockDb.insert.mockResolvedValue(mockPlayground)\n  // Test your actual business logic\n})\n```\n\n### File Testing Approach\n```typescript\n// Create realistic mock files for testing\nconst mockFile = createMockImageFile('test.jpg', 1024 * 100, 'image/jpeg')\n\n// Test actual validation logic\nconst result = await validateImageFile(mockFile)\nexpect(result.isValid).toBe(true)\n```\n\n### Component Testing Pattern\n```typescript\n// Test user behavior, not implementation\n// ✅ Good - tests what user sees\nexpect(screen.getByText('Upload complete')).toBeInTheDocument()\n\n// ❌ Bad - tests internal state\nexpect(component.state.uploadStatus).toBe('complete')\n```\n\n## 🐛 Debugging Tests\n\n### Common Issues & Solutions\n\n#### \"Test timeout\" errors:\n```typescript\n// Add proper waits for async operations\nawait waitFor(() => {\n  expect(screen.getByText('Done')).toBeInTheDocument()\n})\n```\n\n#### \"Mock not called\" errors:\n```typescript\n// Clear mocks between tests\nbeforeEach(() => {\n  vi.clearAllMocks()\n})\n```\n\n#### \"Component not found\" errors:\n```typescript\n// Use proper test queries\n// ✅ Good\nscreen.getByRole('button', { name: /upload/i })\n\n// ❌ Fragile\nscreen.getByTestId('upload-button')\n```\n\n## 📊 Test Coverage\n\n### Current Coverage Targets:\n- **Security functions**: 100% (critical)\n- **Business logic**: 90%+ (important)\n- **UI components**: 80%+ (useful)\n\n### Check Coverage:\n```bash\npnpm test:coverage\n```\n\n**Remember:** Coverage percentage isn't everything. Red - Write failing test\nit('should sanitize dangerous filenames', () => {\n  expect(sanitizeFilename('../../../etc/passwd')).toBe('___etc_passwd')\n  // This will fail initially\n})\n\n// 2. Green - Make it pass\nexport function sanitizeFilename(filename: string): string {\n  return filename.replace(/[^a-zA-Z0-9.-]/g, '_')\n}\n\n// 3. Refactor - Improve implementation\nexport function sanitizeFilename(filename: string): string {\n  return filename\n    .replace(/[^a-zA-Z0-9.-]/g, '_')\n    .replace(/\\.+/g, '.')\n    .replace(/^\\./,'')\n    .substring(0, 100)\n}\n```\n\n## 🚀 Next Steps\n\n### Immediate Actions:\n1. **Install dependencies**: `./install-test-deps.sh`\n2. **Run tests**: `pnpm test:ui`\n3. **Explore test files** to understand patterns\n4. **Break something** and watch tests catch it\n\n### Development Workflow:\n1. **Write failing test** for new feature\n2. **Implement feature** to make test pass\n3. **Refactor** while keeping tests green\n4. **Add edge cases** as you discover them\n\n### Advanced Topics (Future):\n- **Visual regression testing** for UI components\n- **Performance testing** for file operations\n- **Accessibility testing** with axe-core\n- **E2E testing** with Playwright\n\n## 📚 Resources\n\n### Documentation:\n- [Vitest Guide](https://vitest.dev/guide/)\n- [Testing Library Docs](https://testing-library.com/)\n- [MSW Documentation](https://mswjs.io/)\n\n### Best Practices:\n- [Common Testing Mistakes](https://kentcdodds.com/blog/common-mistakes-with-react-testing-library)\n- [Testing Implementation Details](https://kentcdodds.com/blog/testing-implementation-details)\n\n## 💡 Key Takeaways\n\n1. **Tests are documentation** - they show how your code should work\n2. **Fast feedback loops** - tests catch bugs immediately\n3. **Confidence in changes** - refactor without fear\n4. **Better design** - testable code is usually better code\n5. **Security matters** - test your defenses thoroughly\n\n---\n\n**The testing foundation is now solid.
